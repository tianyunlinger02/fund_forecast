# 公开资料与产品背景

## 旧规则检查器已经退出当前建议

此前的多因素v1/v2使用持仓集中度、经理任期、规模、费用、事件和估值等固定阈值限制新增，再用持有天数和问卷判断是否给出卖出。它不是概率预测，现已被[每日预测与决策](forecast.md)替换；不再因固定30天、36个月、某项超线或旧检查机会锁住当前判断。

旧策略定义、检查和验收只属于历史，不重写原数据库或研究结果。保留有用的公开资料，不等于保留旧规则引擎。

## 当前资料的作用

资料应清楚区分四种用途：

1. **预测输入**：具有可对齐的历史时间序列，能按当时可知范围训练、顺序检验；只有实际使用的输入才可称参与概率计算。
2. **产品背景**：当前或较近披露的投向、经理、规模和公告，能帮助理解产品，但不能倒填历史训练，也不凭阈值直接变成买卖禁令。
3. **实际执行数据**：渠道费率、申赎状态、确认与到账安排，用于成本和可执行性，不改变市场概率。
4. **作者投资论证**：有出处的事实、政策/产业传导、支持/反对、价格是否已反映、替代得失和改判条件，影响整只基金新买/持有/加/减/赎姿态。它不是把新闻加分，也不修改概率。

## 公开文件复核导入

这是一项资料维护操作，不是持仓、账户或余额上传。沿用已有CLI名称：

```bash
.venv/bin/rmbfund --root <资料目录> --mode public fund-review-init
.venv/bin/rmbfund --root <资料目录> --mode public fund-review-import \
  <已登记产品ID> <公开原件> --source-url <公开HTTPS地址> \
  --records <记录.json> --reviewed
```

`记录.json`是数组，或仅含`records`的对象。每条需要`family`、`report_date`、`payload`和`locator`；实际`observed_at/available_at`由导入操作记录，不接受伪造。

定位例子：HTML `table:6;row:1`、PDF `page:3;section:费用`、JSON `json:/fees`。PDF定位代表人工核对，不是自动OCR认证。导入只读取本地原件，不请求来源URL，也不执行文件中的JS或其他代码；URL与域名本身不证明文件真实。

相同文件重复本地导入不刷新来源核查时间。修订追加，原件、所属日期、实际取得、定位和最后核对分别保留。保存资料不会创建旧日检、策略启用或订单。

## 费用资料的特别区别

当前公开费率资料有0—6天、7—29天、30天及以上等赎回费段，但实际支付宝费率和持有日口径需要核对。**保留这些真实费率档位，与删除人为30天卖出门槛并不矛盾。**

仅有最近一批确认日，不能精确计算多批份额的加权费用。实际算账需用批次或给出明确的成本范围，不冒充已读取个人交易记录。
